# Task 1.1 — Classification Benchmark for Library Models

This section reports the benchmarking study required in Task 1.1. We compared **logistic regression** (linear & non-linear), **SVM** (linear & kernel), **kNN**, **naive Bayes**, and **random forest**. The report includes training times, accuracy metrics, and a beginner-friendly explanation of how we tuned the **hyperparameters**.

---

## 1) Data & Feature Representation

All classifiers were trained on the same feature matrix produced in Task 0:

- `X_final.npy`: A single vector per sample, created by concatenating:
  - **Metadata** (Weight, Season, Origin, Color)
  - **Text Embeddings** (BERT-based descriptions)
  - **Image Features** (Color Histograms, LBP texture, GLCM)
- `y_final.npy`: The label (fruit/vegetable name), encoded to integers (0, 1, 2...).

The final feature vector has **499 dimensions** per sample. This "fixed length" allows us to feed the data into standard Machine Learning models.

---

## 2) Fair Comparison Setup

### Split
- **Train/Test:** 80% used for training, 20% held out for final testing.
- **Stratified:** We ensured the mix of fruits (e.g., 10% apples, 5% bananas) was identical in both the training and test sets.
- `random_state = 42`: Ensures our results are reproducible.

### Hyperparameter Selection
- We used **GridSearchCV** (Grid Search). This is like a "brute force" method where we gave the computer a list of settings to try, and it tested every single combination.
- **Cross-Validation:** 3-fold. The model was trained 3 times on different parts of the training data to ensure the accuracy wasn't just luck.
- **Metric:** We selected the winner based on **Accuracy**.

### Scaling
- **StandardScaler:** We applied this to **LogReg**, **SVM**, and **kNN**.
- **Reason:** These models calculate mathematical "distances" between points. If one feature is huge (like weight in grams: 120) and another is tiny (color histogram: 0.05), the model gets confused and thinks weight is the only thing that matters. Scaling forces all features to be on the same scale (like converting everything to meters).

**Interpretation:**
- **Linear Models are Kings:** The simple Logistic Regression and Linear SVM achieved ~99.5% accuracy. This proves our dataset is **Linearly Separable**. The features we engineered (Text + Image) successfully placed different fruits in distinct clusters that can be separated by straight lines.
- **Random Forest:** Achieved 100% accuracy but was the slowest (~21s) because it had to build 400 decision trees.

## 4) Hyperparameter Table

Below is the explanation of the "knobs" we turned to get the best performance.

| Classifier | Parameter | Search Range | Best Value | Explanation & Intuition |
| :--- | :--- | :--- | :--- | :--- |
| **LogReg (linear)** | `C` | `[0.1, 1.0, 10.0]` | `0.1` | **The Strict Teacher:** `C` controls how much we punish the model for being complicated. A low `C` (0.1) is a strict teacher—it forces the model to ignore noisy details and keep the math simple. Since we have 499 features (a lot of noise), the strict teacher worked best to prevent the model from memorizing useless details. |
| | `solver` | `['lbfgs']` | `lbfgs` | **The Engine:** This is just the mathematical "engine" used to find the answer. `lbfgs` is the industry standard for these types of problems because it is fast and memory-efficient. |
| **LogReg + RBF Features** | `n_components` | `[300, 800]` | `800` | **Resolution:** This method tries to fake a non-linear kernel by generating random features. `n_components` is like the resolution of a photo. 300 was too blurry. 800 gave a sharper picture, so the model chose it to try and capture as much detail as possible. |
| | `gamma` | `[0.01, 0.1, 1.0]` | `0.01` | **The Blur Level:** Gamma controls how "sharp" or "focused" our random features are. A high gamma creates very sharp features (which can look like noise). A low gamma (0.01) creates broader, smoother features. The model chose the smoother option because it captured general patterns better. |
| **SVM (linear)** | `C` | `[0.1, 1.0, 10.0]` | `0.1` | **The Wide Road:** In SVM, `C` decides how strict the boundary is. A high `C` tries to perfectly separate every single dot (Hard Margin). A low `C` (0.1) creates a "wider road" (Soft Margin), allowing some dots to be on the wrong side if it makes the overall path smoother. The model preferred the wider road, which is safer and less likely to crash on new data. |
| **SVM (RBF Kernel)** | `gamma` | `['scale', 0.01, 0.05]` | `scale` | **Auto-Zoom:** Gamma controls the "reach" of a single data point. `scale` is a smart formula that automatically calculates the perfect "zoom level" based on how spread out our data is. It saves us from guessing the right number manually. |
| | `C` | `[0.5, 1.0, 5.0]` | `5.0` | **Looser Constraints:** Interestingly, the non-linear SVM chose a higher `C` (5.0) than the linear version. This means in the non-linear projection, it needed to fit the data more aggressively to achieve high accuracy. |
| **kNN** | `n_neighbors` | `[3, 5, 9]` | `3` | **Small Circle of Friends:** kNN works by asking neighbors for advice. If `k=3`, it asks its 3 closest friends. If `k=9`, it asks a larger group. The model chose 3, which means our fruit clusters are very tight. If a fruit looks like a Banana, its 3 closest neighbors are *all* Bananas. We don't need to search further. |
| | `weights` | `['uniform', 'distance']` | `uniform` | **Democracy:** "Uniform" means every neighbor gets 1 full vote. "Distance" gives closer neighbors more voting power. The model chose "Uniform," implying our clusters are trustworthy—even the slightly further neighbors are reliable enough to have a full vote. |
| **Naive Bayes** | `var_smoothing` | `[1e-9, 1e-8, 1e-7]` | `1e-8` | **The Safety Net:** Naive Bayes uses division in its math. If a feature has zero variance (e.g., a pixel that is always black), the computer tries to divide by zero and crashes. This parameter adds a tiny number to the variance to act as a safety net. |
| **Random Forest** | `n_estimators` | `[200, 400]` | `400` | **Committee Size:** A Random Forest is like a committee of voters (trees). `n_estimators` is the number of people in the committee. The model chose 400 (the largest option) because generally, having more people vote cancels out individual errors and leads to a more stable final decision. |
| | `max_depth` | `[None, 20, 40]` | `None` | **Freedom to Learn:** This limits how many questions a tree can ask. `None` means "ask as many questions as you want." The model used this freedom to perfectly distinguish every single fruit, achieving 100% accuracy. |
| | `min_samples_leaf` | `[1, 2]` | `2` | **Minimum Group Size:** This rule says, "You cannot create a category for just 1 person." A leaf must have at least 2 samples. This prevents the model from memorizing a single weird-looking apple (overfitting). |
| | `max_features` | `['sqrt', 'log2']` | `sqrt` | **Limited View:** To ensure the committee members don't all think alike, each tree is only allowed to look at a random subset of features ($\sqrt{499} \approx 22$) at each step. This forces diversity, which makes the "Forest" smarter than any single "Tree." |

## 5) Discussion: Accuracy vs Time Trade-off

- **Best Accuracy:** Random Forest (Test = 1.00), but it was the **slowest** to train.
- **Best Efficiency:** Linear SVM achieved ~0.995 test accuracy with extremely fast training time (under 1 second).
- **Conclusion:** Since the Linear SVM is 20x faster than Random Forest and only 0.5% less accurate, it is likely the "best" model for a real-world production system where speed matters.
