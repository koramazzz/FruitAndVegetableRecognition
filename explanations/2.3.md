# Task 2.3 — Outlier Detection: Clustering vs. SVM

[cite_start]This section proposes a second outlier detection framework based on **Clustering Density** and compares it with the **SVM Slack** framework from Task 1.6(a)[cite: 40, 41].

---

## 1) Proposed Framework: "The Loner"

While the SVM framework looked for points that **crossed the boundary** (Margin Violators), this Clustering framework looks for points that are **alone** (Density Outliers).

### The Algorithm
1.  **Reduce:** Apply PCA to compress the data (removing noise).
2.  **Cluster:** Fit K-Means ($k=5$) to find the center (centroid) of each fruit group.
3.  **Measure:** Calculate the Euclidean distance of every image to its assigned centroid.
4.  **Detect:** Images that are "too far" (in the 99.5th percentile of distance) are flagged as outliers.

**Intuition:** If most apples are 5 units away from the center, but one specific apple is 25 units away, that apple is an anomaly.

### Visual Inspection
* **SVM detected:** Images that looked like *other* fruits (e.g., a round potato that looked like a mandarin). These are "Boundary Cases."
* **Clustering detected:** Images that looked like *weird* versions of themselves (e.g., a banana that was extremely curved or dark). These are "intra-class variations" that don't necessarily confuse the classifier but are statistically rare.


---

## 3) Conclusion on Outliers

The two frameworks detect fundamentally different types of anomalies:
1.  **Clustering** finds **Atypical Samples** (e.g., a rotten apple). These might still be easily classified as apples, just weird ones.
2.  **SVM** finds **Ambiguous Samples** (e.g., an apple that looks like a tomato). These are the dangerous ones for the model.

For a robust production system, **SVM-based detection** is more valuable because it highlights the specific data points that confuse the model, whereas Clustering simply highlights variety.
